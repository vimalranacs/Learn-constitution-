# Authentication boundary

The first deployment is owner-private through Sites. Production pages additionally call the starter's server-only `requireChatGPTUser`; entity API rejects absent identity. Trust forwarded identity headers only behind Sites dispatch. Do not deploy this identity adapter on an unprotected public Worker URL.

Local development serves only public constitutional material and bypasses login under development mode. It does not implement or store personal data. There is no public signup, friend access, allowlist editor or durable progress yet.

Before enabling friends: verify Sites' supported audience policy, add explicit approved membership if needed, key D1 records by server-supplied stable user ID, test unauthorized and revoked identities, test two users cannot read or overwrite each other's notes/progress. Client-supplied user IDs must never select data ownership. This acceptance gate remains open.
